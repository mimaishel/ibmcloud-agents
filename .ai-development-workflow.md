# AI-Readable Development Workflow Guide

## Development Environment Setup

### Prerequisites
- **Python**: 3.12+
- **Package Manager**: [uv](https://docs.astral.sh/uv/) (required)
- **Container Runtime**: Podman or Docker (optional, for containerization)
- **IBM Cloud CLI**: Auto-installed via container build

### Quick Start Commands
```bash
# 1. Install uv package manager
curl -LsSf https://astral.sh/uv/install.sh | sh

# 2. Clone repository  
git clone https://github.com/ccmitchellusa/ibmcloud-base-agent.git
cd ibmcloud-base-agent

# 3. Install dependencies
uv sync --reinstall

# 4. Configure environment
cp .env.example .env
# Edit .env with your API keys

# 5. Start development server
./run.sh
```

## Creating New Agents

### Step-by-Step Agent Creation

1. **Create Agent Directory**
   ```bash
   mkdir src/my_new_agent
   cd src/my_new_agent
   ```

2. **Create Agent Module** (`agent.py`)
   ```python
   from src.ibmcloud_base_agent.agent import IBMCloudBaseAgent
   
   def create_my_new_agent(**kwargs):
       agent_factory = IBMCloudBaseAgent()
       return agent_factory.create_agent(
           name="my_new_agent",
           description="Description of what this agent does",
           instruction="""
           System prompt defining agent behavior and expertise.
           Include specific IBM Cloud context and tool usage patterns.
           """,
           mcp_tools="tool1,tool2,tool3",  # Comma-separated MCP tools
           mcp_server_name="my-new-server",
           config_file="my_new_agent_config.json",
           **kwargs
       )
   
   # Create default instance
   root_agent = create_my_new_agent()
   ```

3. **Create MCP Configuration** (`my_new_agent_config.json`)
   ```json
   {
     "mcpServers": {
       "my-new-server": {
         "command": "ibmcloud",
         "args": [
           "--mcp-transport", "stdio",
           "--mcp-tools", "tool1,tool2,tool3"
         ]
       }
     }
   }
   ```

4. **Add Agent to Server Configuration** (`agent.yaml`)
   ```yaml
   my_new_agent:
     type: a2a_server.tasks.handlers.chuk.chuk_agent_handler.AgentHandler
     agent: my_new_agent.agent.root_agent
     name: my_new_agent
     
     # Configuration settings...
     provider: "openai"
     model: "gpt-4o-mini"
     enable_tools: true
     mcp_config_file: "my_new_agent_config.json"
     mcp_servers: ["my-new-server"]
     
     agent_card:
       name: "My New Agent 🚀"
       description: "Agent description for A2A cards"
       skills:
         - id: my_skill
           name: "My Skill"
           description: "What this skill does"
           examples:
             - "Example prompt 1"
             - "Example prompt 2"
   ```

5. **Create Tests**
   ```bash
   mkdir tests/unit/my_new_agent
   touch tests/unit/my_new_agent/test_agent.py
   ```

6. **Test New Agent**
   ```bash
   # Test standalone
   cd src && uv run -m my_new_agent.main
   
   # Test via server
   ./run.sh
   uvx a2a-cli --server http://localhost:8000/my_new_agent chat
   ```

### Custom Handler Creation

For advanced coordination patterns (like Supervisor/Kingsmen), create custom handlers:

1. **Create Handler Class**
   ```python
   from a2a_server.tasks.handlers.base_handler import BaseHandler
   
   class MyCustomHandler(BaseHandler):
       async def handle_message(self, message, context):
           # Custom message handling logic
           pass
   ```

2. **Register Handler in agent.yaml**
   ```yaml
   my_custom_agent:
     type: src.my_custom_agent.my_handler.MyCustomHandler
     # Additional configuration...
   ```

## Containerization Workflow

### Local Container Development
```bash
# Build container
podman build -t ibmcloud-agents:latest .

# Run container locally
podman run --rm -d --env-file=.env -p 8000:8000 ibmcloud-agents:latest

# Test container
curl http://localhost:8000/agent-card.json
```

### Build Arguments
```bash
# Customize Python version
podman build --build-arg PYTHON_VERSION=3.13 -t ibmcloud-agents:latest .

# Customize IBM Cloud CLI
podman build \
  --build-arg IBMCLOUD_VERSION=2.35.0 \
  --build-arg IBMCLOUD_ARCH=amd64 \
  --build-arg IBMCLOUD_PLUGINS="project,code-engine" \
  -t ibmcloud-agents:latest .
```

## IBM Cloud Deployment Workflow

### Code Engine Deployment (Serverless)

1. **Create Code Engine Project**
   ```bash
   ibmcloud ce project create --name my-agents
   ibmcloud ce project select --name my-agents
   ```

2. **Deploy from Source**
   - Navigate to Code Engine console
   - Create application from source code repository
   - Set listening port to 8000
   - Configure environment variables

3. **Deploy from Container Registry**
   ```bash
   # Push to IBM Container Registry
   ibmcloud cr login
   ibmcloud cr namespace-add my-namespace
   podman build --push -t icr.io/my-namespace/ibmcloud-agents .
   
   # Create Code Engine application
   ibmcloud ce app create --name ibmcloud-agents --image icr.io/my-namespace/ibmcloud-agents
   ```

### Supporting Services Setup

```bash
# Create IBM Cloud services for production
make ibmcloud-services-setup

make ibmcloud-services-env

make ibmcloud-all
```

## Debugging and Troubleshooting

### Debug Mode
```bash
# Enable debug logging
cd src && uv run -m ibmcloud_base_agent.main --config ../agent.yaml --log-level debug

# Enable MCP tool debugging
# Set debug_tools: true in agent.yaml
```

### Common Issues
1. **MCP Tools Unavailable**: Check ibmcloud CLI installation and API key
2. **Agent Not Responding**: Verify endpoint configuration in agent.yaml
3. **Model Provider Issues**: Check API keys and provider configuration
4. **Container Build Fails**: Verify build arguments and base image

### Log Analysis
```bash
# View agent logs
tail -f logs/agent.log

# Analyze MCP communication
grep "MCP" logs/agent.log

# Check delegation patterns (Supervisor/Kingsmen)
grep "delegation\|routing" logs/agent.log
```

## Best Practices

### Code Quality
- Use type hints throughout
- Follow Black code formatting
- Maintain test coverage >80%
- Document all public APIs

### Security
- Never commit API keys to repository
- Use environment variables for secrets
- Follow least privilege for IBM Cloud access
- Validate all user inputs

### Performance  
- Use streaming responses for better UX
- Implement proper session management
- Monitor token usage and costs
- Cache expensive operations when possible

### Maintainability
- Keep agent instructions focused and clear
- Use consistent naming conventions
- Implement proper error handling
- Maintain backward compatibility in APIs
