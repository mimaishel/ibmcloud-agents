# AI-Readable Agent Configuration Guide

## Agent Configuration Structure

All agents in this project follow a consistent YAML configuration pattern in `agent.yaml`. Each agent configuration includes:

### Core Configuration Elements

```yaml
agent_name:
  type: handler_class_path
  agent: agent_module_path
  name: agent_identifier
```

### Session Management
```yaml
# Handler-level session configuration
sandbox_id: "unique_session_namespace"
session_sharing: false

# Agent-level session configuration
enable_sessions: true|false
infinite_context: true
token_threshold: 4000
max_turns_per_segment: 50
session_ttl_hours: 24
```

### Model Configuration
```yaml
provider: "openai|anthropic|litellm"
model: "gpt-4o-mini|claude-3-sonnet|etc"
streaming: true
```

### MCP Tool Configuration
```yaml
enable_tools: true
debug_tools: false
mcp_config_file: "agent_specific_config.json"
mcp_servers: ["server-name"]
mcp_transport: "stdio"
```

### Agent Card (A2A Protocol)
```yaml
agent_card:
  name: "Display Name 🔥"
  description: "Agent purpose and capabilities"
  version: "1.0.0"
  documentationUrl: "https://github.com/repo/docs"
  provider:
    organization: "org_name"
    url: "contact_url"
  capabilities:
    streaming: true
    pushNotifications: false
  authentication:
    schemes: ["None"]
  defaultInputModes: ["text/plain"]
  defaultOutputModes: ["text/plain"]
  skills:
    - id: skill_identifier
      name: "🔧 Skill Display Name"
      description: "What this skill does"
      tags: ["tag1", "tag2"]
      examples:
        - "Example prompt 1"
        - "Example prompt 2"
```

## Agent-Specific Configurations

### Base Agent
- **Purpose**: Core template and basic resource management
- **MCP Tools**: `resource-management`
- **Key Skills**: Resource targeting, listing, account scoping
- **Session Management**: Disabled for utility-focused operations

### Serverless Agent  
- **Purpose**: IBM Cloud Code Engine management
- **MCP Tools**: `serverless-computing`
- **Key Skills**: Application deployment, project management, monitoring
- **Session Management**: Disabled for stateless operations

### Guide Agent
- **Purpose**: IBM Cloud documentation assistant
- **MCP Tools**: `ibm-cloud-guide` 
- **Key Skills**: Documentation search, best practices, architecture guidance
- **Session Management**: Disabled for reference operations

### Account Admin Agent
- **Purpose**: User and IAM management
- **MCP Tools**: `account-admin`
- **Key Skills**: User management, access policies, service IDs, API keys
- **Session Management**: Disabled for security-focused operations

### Cloud Automation Agent
- **Purpose**: Deployment architectures and automation
- **MCP Tools**: `cloud-automation`
- **Key Skills**: Deployable architectures, projects, Schematics, Terraform
- **Session Management**: Disabled for automation tasks

### Supervisor Agent
- **Purpose**: Intelligent task delegation
- **MCP Tools**: None (uses HTTP delegation)
- **Key Skills**: LLM-powered routing, multi-agent coordination
- **Session Management**: Enabled for coordination context
- **Special Config**: 
  ```yaml
  agent_urls:
    - "http://localhost:8000/ibmcloud_base_agent"
    - "http://localhost:8000/ibmcloud_account_admin_agent"
    # ... other agent URLs
  ```

### Kingsmen Agent
- **Purpose**: Elite team coordination with codenames
- **MCP Tools**: None (uses HTTP delegation) 
- **Key Skills**: Team coordination, expertise routing, specialized delegation
- **Session Management**: Enabled for team context
- **Special Config**:
  ```yaml
  team_environment: "localhost"
  ```

## MCP Configuration Files

Each agent with MCP tools has a corresponding JSON configuration file:

```json
{
  "mcpServers": {
    "server-name": {
      "command": "ibmcloud",
      "args": [
        "--mcp-transport", "stdio",
        "--mcp-tools", "tool1,tool2,tool3"
      ]
    }
  }
}
```

### Tool Categories by Agent

| Agent | MCP Tools | Capabilities |
|-------|-----------|-------------|
| Base | `resource-management` | Target, list resources, search |
| Serverless | `serverless-computing` | Code Engine projects, apps, jobs |
| Guide | `ibm-cloud-guide` | Documentation, best practices |
| Account Admin | `account-admin` | Users, IAM, service IDs, policies |
| Cloud Automation | `cloud-automation` | Deployable architectures, projects |

## Environment Variable Configuration

### Required Variables
```bash
# LLM Provider Configuration
OPENAI_API_KEY=your_openai_key
PROVIDER=openai
MODEL=gpt-4o-mini

# IBM Cloud Authentication  
IBMCLOUD_API_KEY=your_ibmcloud_key
IBMCLOUD_REGION=us-south
```

### Optional Service Integration
```bash
# IBM Cloud Monitoring
IBMCLOUD_MONITORING_ENABLED=true
IBMCLOUD_MONITORING_INSTANCE=agent-monitoring
IBMCLOUD_MONITORING_OTEL_ENDPOINT=endpoint_url
IBMCLOUD_MONITORING_ACCESS_KEY=access_key

IBMCLOUD_LOGS_ENABLED=true
IBMCLOUD_LOGS_INSTANCE=agent-logs
IBMCLOUD_LOGS_ENDPOINT=logs_endpoint

LITELLM_PROXY_MODEL=custom_model
```

## Agent Creation Pattern

All agents extend the `IBMCloudBaseAgent` class:

```python
from src.ibmcloud_base_agent.agent import IBMCloudBaseAgent

class CustomAgent(IBMCloudBaseAgent):
    def create_agent(self, **kwargs):
        return self.create_agent(
            name="custom_agent",
            description="Agent description",
            instruction="System prompt...",
            mcp_tools="tool1,tool2",
            mcp_server_name="server-name", 
            config_file="config.json",
            **kwargs
        )
```

## Handler Implementation

Agents use different handler types:

1. **ChukAgentHandler**: Standard MCP-enabled agents
   ```yaml
   type: a2a_server.tasks.handlers.chuk.chuk_agent_handler.AgentHandler
   ```

2. **SupervisorHandler**: Delegation-focused agents
   ```yaml
   type: src.supervisor_agent.supervisor_handler.SupervisorHandler
   ```

3. **KingsmenHandler**: Team coordination agents
   ```yaml
   type: src.kingsmen_agent.kingsmen_handler.KingsmenHandler
   ```

## Default Agent Configuration

The server uses `supervisor_agent` as the default handler:

```yaml
handlers:
  use_discovery: false
  default: supervisor_agent
```

This means connecting to the root server URL will automatically route to the Supervisor Agent, which can then delegate to specialized agents as needed.
