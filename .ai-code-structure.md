## Core Components

### Base Agent Template (`src/ibmcloud_base_agent/`)

**Purpose**: Provides the foundational template and utilities for all IBM Cloud agents.

**Key Files**:
- `agent.py`: IBMCloudBaseAgent class definition and template patterns
- `main.py`: Standalone agent entry point
- `__init__.py`: Module initialization

**Core Classes**:
```python
class IBMCloudBaseAgent:
    def __init__(self)
    def _create_provider_config(self) -> ProviderConfig
    def _create_mcp_config(self, config_file, mcp_tools, server_name, allow_write)
    def create_agent(self, name, description, instruction, mcp_tools, **kwargs) -> ChukAgent

# Factory function
def create_base_agent(**kwargs) -> ChukAgent
```

**Agent Creation Pattern**: All agents follow this template for consistent MCP integration, fallback handling, and configuration.

### Common Utilities (`src/common/`)

**Purpose**: Shared services and utilities used across all agents.

**Key Files**:
- `services.py`: IBM Cloud services integration (monitoring, logging, storage)
- `simple_a2a_client.py`: A2A protocol client for inter-agent communication
- `types.py`: Common type definitions and data structures

**Key Classes**:
```python
# services.py
class ServiceConfig
class MonitoringConfig  
class LoggingConfig
class StorageConfig

# simple_a2a_client.py
class SimpleA2AClient:
    def __init__(self, base_url)
    async def send_message(self, message, agent_endpoint)
    async def get_agent_card(self, agent_endpoint)

# types.py  
class AgentResponse
class ChatMessage
class AgentCard
```

### Advanced Coordination Agents

#### Supervisor Agent (`src/supervisor_agent/`)

**Purpose**: Intelligent task delegation using LLM-powered routing.

**Key Files**:
- `supervisor_handler.py`: Custom A2A handler for delegation logic
- `agent.py`: Agent implementation (minimal, delegates to handler)
- `team_management.py`: Dynamic team member management
- `README.md`: Detailed supervisor documentation

**Key Classes**:
```python
class SupervisorHandler(BaseHandler):
    def __init__(self, config)
    async def handle_message(self, message, context)
    async def _route_to_agent(self, message, selected_agent_url)
    def _select_agent(self, message_content) -> str

class SupervisorAgent:
    def __init__(self)
    def create_supervisor_agent(self, **kwargs) -> ChukAgent
```

**Architecture**: 
- Uses HTTP delegation instead of MCP tools
- Maintains list of agent URLs for routing
- LLM analyzes requests to select appropriate specialist
- Forwards requests and returns responses transparently

## Configuration Files

### MCP Tool Configurations
Located in `src/` directory, each agent has an MCP config file:

```json
// ibmcloud_mcp_*_config.json
{
  "mcpServers": {
    "server-name": {
      "command": "ibmcloud",
      "args": ["--mcp-transport", "stdio", "--mcp-tools", "tool1,tool2"]
    }
  }
}
```

### Agent Server Configuration (`agent.yaml`)
```yaml
handlers:
  use_discovery: false
  default: supervisor_agent

  agent_name:
    type: handler_class_path
    agent: agent_module_path
    # ... configuration details
```

## Data Flow Architecture

### Standard Agent Flow
```
User Request → A2A Endpoint → ChukAgentHandler → ChukAgent → MCP Tools → IBM Cloud API
```

### Supervisor Agent Flow  
```
User Request → A2A Endpoint → SupervisorHandler → LLM Routing → Target Agent → Response
```

### Kingsmen Agent Flow
```
User Request → A2A Endpoint → KingsmenHandler → Codename Resolution → Specialist Agent → Response  
```

## Key Design Patterns

### Agent Factory Pattern
All agents use factory functions (`create_*_agent()`) for consistent instantiation with default configurations.

### Handler Strategy Pattern  
Different handler types (ChukAgentHandler, SupervisorHandler, KingsmenHandler) implement different coordination strategies.

### MCP Integration Pattern
Standardized MCP configuration generation and fallback handling across all agents.

### Configuration-Driven Architecture
Agent behavior primarily driven by YAML configuration rather than hard-coded values.

## Extension Points for New Agents

1. **Create Agent Directory**: `src/new_agent_name/`
2. **Implement Agent Class**: Extend `IBMCloudBaseAgent`  
3. **Add to agent.yaml**: Configure handler and endpoints
4. **Create MCP Config**: Define required tools
5. **Add Tests**: Unit and integration tests
6. **Update Documentation**: Add to agent cards and README

This structure enables easy extensibility while maintaining consistency across all agent implementations.
