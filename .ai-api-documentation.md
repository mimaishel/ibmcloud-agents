# AI-Readable API Documentation

## Server Configuration
- **Base URL**: `http://localhost:8000` (development)
- **Protocol**: A2A (Agent-to-Agent)
- **Port**: 8000
- **Framework**: a2a-server

## Core Endpoints

### Agent Card Endpoint
```
GET /agent-card.json
```
Returns server-level agent card information including all available agents.

**Response Format**: JSON
```json
{
  "name": "IBM Cloud Agents Server",
  "agents": [
    {
      "name": "Agent Name",
      "endpoint": "/agent_path",
      "description": "Agent description"
    }
  ]
}
```

## Agent-Specific Endpoints

### Base Agent
```
POST /ibmcloud_base_agent
GET  /ibmcloud_base_agent/agent-card.json
```
- **Purpose**: Core IBM Cloud resource management
- **Capabilities**: Resource targeting, listing, account scoping
- **MCP Tools**: resource-management
- **Session Management**: Disabled

### Serverless Agent  
```
POST /ibmcloud_serverless_agent
GET  /ibmcloud_serverless_agent/agent-card.json
```
- **Purpose**: IBM Cloud Code Engine management
- **Capabilities**: Application deployment, project management, monitoring
- **MCP Tools**: serverless-computing  
- **Session Management**: Disabled

### Guide Agent
```
POST /ibmcloud_guide_agent
GET  /ibmcloud_guide_agent/agent-card.json
```
- **Purpose**: IBM Cloud documentation and guidance
- **Capabilities**: Documentation search, best practices, architecture guidance
- **MCP Tools**: ibm-cloud-guide
- **Session Management**: Disabled

### Account Admin Agent
```
POST /ibmcloud_account_admin_agent  
GET  /ibmcloud_account_admin_agent/agent-card.json
```
- **Purpose**: Account administration and IAM management
- **Capabilities**: User management, access policies, service IDs, API keys
- **MCP Tools**: account-admin
- **Session Management**: Disabled

### Cloud Automation Agent
```
POST /ibmcloud_cloud_automation_agent
GET  /ibmcloud_cloud_automation_agent/agent-card.json
```
- **Purpose**: Cloud automation and deployment architectures
- **Capabilities**: Deployable architectures, projects, Schematics, Terraform
- **MCP Tools**: cloud-automation
- **Session Management**: Disabled

### Supervisor Agent (Default)
```
POST /supervisor_agent
POST /  (routes to supervisor_agent)
GET  /supervisor_agent/agent-card.json
```
- **Purpose**: Intelligent task delegation to specialized agents
- **Capabilities**: LLM-powered routing, multi-agent coordination, task delegation
- **Session Management**: Enabled
- **Default Handler**: Yes

### Kingsmen Agent
```
POST /kingsmen_agent
GET  /kingsmen_agent/agent-card.json
```
- **Purpose**: Elite team coordination with specialized codenames
- **Capabilities**: Team coordination, expertise routing, specialized delegation  
- **Session Management**: Enabled

## Request/Response Format

### Chat Request (POST)
All chat endpoints accept A2A protocol messages:

```json
{
  "messages": [
    {
      "role": "user",
      "content": "Your message here"
    }
  ],
  "stream": true,
  "session_id": "optional-session-id"
}
```

## Client Integration

### A2A CLI Client
```bash
# Connect to default agent (supervisor)
uvx a2a-cli --server http://localhost:8000 chat

# Connect to specific agent
uvx a2a-cli --server http://localhost:8000/ibmcloud_base_agent chat

# Switch agents during session
/connect http://localhost:8000/ibmcloud_serverless_agent
```

### HTTP Client Examples

#### cURL Examples
```bash
# Get agent card
curl -X GET http://localhost:8000/ibmcloud_base_agent/agent-card.json

# Send chat message
curl -X POST http://localhost:8000/ibmcloud_base_agent \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [
      {
        "role": "user", 
        "content": "List my resource groups"
      }
    ],
    "stream": false
  }'

# Streaming request
curl -X POST http://localhost:8000/supervisor_agent \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [
      {
        "role": "user",
        "content": "Help me deploy a serverless app"
      }
    ],
    "stream": true
  }' \
  --no-buffer
```

#### Python Client Example
```python
import requests
import json

# Send message to agent
response = requests.post(
    'http://localhost:8000/supervisor_agent',
    headers={'Content-Type': 'application/json'},
    json={
        'messages': [
            {'role': 'user', 'content': 'List my IBM Cloud resources'}
        ],
        'stream': False
    }
)

result = response.json()
print(result['content'])
```

## Agent Routing Logic

### Supervisor Agent Delegation
The Supervisor Agent uses LLM-powered routing to delegate tasks:

1. Analyzes user request
2. Determines most appropriate specialized agent
3. Forwards request to target agent
4. Returns response to user

**Agent Selection Criteria**:
- Base Agent: General resource management, targeting, listing
- Serverless Agent: Code Engine, applications, serverless deployment
- Guide Agent: Documentation questions, best practices
- Account Admin Agent: Users, IAM, access policies, service IDs
- Cloud Automation Agent: Deployable architectures, projects, Terraform

### Kingsmen Agent Team Routing
The Kingsmen Agent coordinates specialized team members:

**Team Members**:
- **Galahad**: Foundation specialist (basic operations)
- **Lancelot**: Security specialist (access management)
- **Percival**: Serverless specialist (Code Engine)
- **Gareth**: Strategy specialist (architecture, planning)
- **Tristan**: Automation specialist (deployment, pipelines)

## Session Management

### Session-Enabled Agents
- Supervisor Agent: Maintains delegation context
- Kingsmen Agent: Maintains team coordination context

### Session Configuration
```json
{
  "session_id": "unique-identifier",
  "ttl_hours": 24,
  "infinite_context": true,
  "token_threshold": 4000,
  "max_turns_per_segment": 50
}
```

## Error Handling

### Common HTTP Status Codes
- `200`: Successful request
- `400`: Bad request (invalid JSON or parameters)
- `404`: Agent endpoint not found
- `500`: Internal server error
- `503`: Service unavailable (MCP tools offline)

### Error Response Format
```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Human readable error description",
    "details": "Additional context if available"
  }
}
```

## Production Deployment Endpoints

### IBM Cloud Code Engine
When deployed to Code Engine, endpoints follow the pattern:
```
https://ibmcloud-agents.{project-id}.{region}.codeengine.appdomain.cloud/
```

Example:
```
https://ibmcloud-agents.1uo9xqkaspg3.us-east.codeengine.appdomain.cloud/supervisor_agent
```

### Load Balancing
For production deployments with multiple instances:
- Use Code Engine's built-in load balancing
- Session affinity not required (agents are stateless except supervisor/kingsmen)
- Health checks available at `/health` endpoint

## Monitoring and Observability

### Health Check Endpoint
```
GET /health
```
Returns server health status and agent availability.

### Metrics Endpoint (if monitoring enabled)
```
GET /metrics
```
Prometheus-compatible metrics for monitoring agent performance.

### Integration with IBM Cloud Services
When configured with optional services:
- **Monitoring**: OTEL metrics sent to IBM Cloud Monitoring
- **Logging**: Application logs sent to IBM Cloud Logs  
- **Storage**: Session data stored in Object Storage
